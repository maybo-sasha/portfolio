AI builds the journey. Marketers stay in control.

Streams turns a marketing brief into a customer journey. Marketers can review the steps, check expected reach and understand the AI decisions behind each send. Screens show sample data.

The challenge

Reviewing an AI-generated journey

Generating a journey from a prompt was becoming standard, so it could not be what set Streams apart. The harder problem comes right after: the marketer is now responsible for a plan they did not assemble.

I led the design direction around that problem. Streams had to make the AI’s assumptions, reach and choices clear enough for a marketer to check them, change them and stand behind the result.

One rule shaped the rest: a journey written once is still a fixed journey, whether a person or an AI wrote it. So I separated what the marketer authors from what the system decides for each customer.

Discovery & definition

Main UX decisions

Team walkthroughs focused the design on three questions: how to express intent, where to review the journey and how much control to hand over.

01 · Starting point

Brief-led setup

I designed one composer for a complete plan, an idea built line by line or a recipe. Marketers can start with what they know without mapping every step first.

02 · Workspace

Journey in context

I compared a permanent flowchart, chat alone and a workspace that adapts. An answer needs a visible place to land, so the journey stays beside chat and the rest of the workspace changes with the question.

03 · Control

Autonomy levels

A brand mid-migration wants no changes. Two years in, it wants six journeys to become sixty. So each Stream has one autonomy control, from Fixed to Supervised, and opens at Supervised: nothing reaches a customer until the marketer approves it.

UX decisions & flows

Checks vs advice

I separated build approval from launch. Approval moves the journey into a dry run, where findings can lead back to the canvas for a fix.

The bigger split is inside that review. A check states a fact and is always on. Advice is a judgment, so it stays optional and belongs in the build. An earlier assistant had mixed the two: it suggested a control group to people who had already decided against one, they stopped reading it, and the useful checks went with it.

From brief to build

Reviewable plan

I combined free-text input with audience and flow-block shortcuts, so marketers can describe an idea and reference existing building blocks in the same brief.

The journey builds step by step, with a summary of the brief for the marketer to approve.

Advice in the build

Tradeoffs before accepting

Build suggestions arrive under the brief once the Stream is built, so the marketer reads the journey first and the advice second. This is where the AI asks permission for what it should not assume, such as giving away an offer.

Each one shows what would change and the tradeoff, with a clear way to say no. Accepting names what it changed, with Undo beside it. A declined suggestion does not come back.

I first held some of this advice back for the dry run, then moved it here. A dry run is for checking, and advice is easier to act on before a plan has been through approvals.

The dry run

Dry run

I made the dry run the moment the plan gets checked, not a formality before launch. It runs the approved journey against its audience and shows who reaches each step, on which channel, and what it is worth.

The one suggestion a dry run earns is on a send the marketer just added to fix a finding. That finishes their own change instead of second-guessing a plan they approved.

The canvas

Results on the canvas

A choice means little away from its result, so both stay on screen with the journey. Each is read on the step it belongs to, with the wider Stream’s performance in view.

Layers

Progressive detail

Showing every audience count, timing rule and AI choice at once would overwhelm the canvas, so I split the detail into eight layers that marketers combine around their question.

Step detail starts off, so the canvas opens on the Stream’s shape and a whole journey fits on one screen. All layers use the same steps, so switching never loses your place.

Measure

Step density

Handing decisions to a model only works if the numbers can be trusted, so measurement sits on the canvas, not in a report at the end. Marketers choose up to four measures for their goal, and every step shows exactly those.

Transparency

Decision explainability

A marketer cannot stand behind decisions they cannot see.

Everything the agents do in a running Stream is in the feed, and each update leads straight to its step. Any decision opens to show the signal, the alternatives, the allocation and how it compares with the marketer’s setup.

Streams uses the AI Decisioning agents rather than growing its own, so one choice has one explanation across products.

Chat and canvas

Editing by chat or by hand

I treated the chat and the canvas as one tool. Conversation is the way in, not the whole product. Anything on the journey can be changed by asking, in the marketer’s own words, and nothing moves until they have seen what it changes.

It works at any size, from a timing to a whole new campaign, and always before the dry run, so the check runs on the journey that will go live.

On the canvas

Direct manipulation

What the AI decided stays open to override, so the canvas had to be a place to build, not only to view. Drop a step from Flow blocks onto any connector and it slots in, with the steps below making room.

Grouping, notes and a day ruler keep a long journey readable, without changing its logic.
